# Why TPF Exists

This reader journey begins with the questions that usually arrive before someone has opened a reference page: “Does this replace Spring?”, “Is it another workflow engine?”, and “Why should I change code that already works?”

TPF is not an argument against frameworks, service layers, Clean Architecture, or direct I/O. It is an argument for making consequential business flows explicit when their typed behavior and operational boundaries need to evolve together.
